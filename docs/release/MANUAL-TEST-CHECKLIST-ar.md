# قائمة الاختبار اليدوي الشامل — العمرة والموافقة الأمنية لمصر

**أين:** على بيئة Staging فقط بعد اعتماد النشر عليها، وعلى هاتف أندرويد حقيقي بالنسخة التجريبية (APK QA) التي تتصل بـ Staging.

**كيف:**
- استخدم بيانات اختبار واضحة (اسم يبدأ بـ «اختبار»).
- لا تُجرِ تحويلات مالية حقيقية: الإيصالات ملفات تجريبية.

**ماذا تسجل:** لكل بند: ✅ نجح / ❌ فشل (مع لقطة شاشة ورقم الطلب) / ⏭️ لم يُختبر.

## 0. قبل البدء (المسؤول)

- [ ] تأكد من وجود نسخة احتياطية حقيقية من Staging، وأن الاسترجاع منها نجح (`docs/RELEASE-91-RAILWAY-RUNBOOK.md` §2–3).
- [ ] تأكد من أن أسعار العمرة الثلاثة ثابتة ومفعّلة: تأشيرة فقط، طيران، بحر.
- [ ] تأكد من أن سعري مصر (جوي وبري) ثابتان ومفعّلان.
- [ ] تأكد من وجود حساب بنكي واحد على الأقل مفعّل لكل عملة.
- [ ] تأكد من أن سعر صرف SAR→SDG مفعّل، إن كان مطلوبًا عرض المقابل بالجنيه.
- [ ] جهّز حسابات موظفين بالأدوار الأربعة: مدير أعلى، مدير، موظف عمليات، محاسب.
- [ ] تأكد من إعداد متغيرات البيئة: `WHATSAPP_*` لرموز التتبع، و`PROVIDER_EMAIL_*` لإرسال الإيصال بالبريد، و`UPLOAD_ROOT` على قرص دائم. لا تضبط `PUBLIC_INTAKE_SCOPE`: غيابه يعني النطاق المعتمد.

## 1. العميل — الموقع (هاتف 390px + كمبيوتر)

### النطاق
- [ ] القائمة العلوية والتذييل وصفحة «الخدمات» تعرض العمرة والموافقة الأمنية لمصر فقط.
- [ ] فتح `/flights` أو `/visas` برابط مباشر يعرض الصفحة، لكن **إرسال طلب منها يُرفض** برسالة: «هذه الخدمة غير متاحة للطلب حاليًا…».
- [ ] نموذج «تواصل معنا» (استفسار عام) يُرسل بنجاح.

### العمرة
- [ ] الباقات الثلاث تظهر بسعرها الثابت لكل معتمر، ومعها المقابل بالجنيه إن وُجد سعر صرف.
- [ ] عبارة «يبدأ من … SAR» تُقرأ صحيحة من اليمين.
- [ ] تتم بيانات مقدم الطلب، وهاتف الضامن (إلزامي)، وتاريخ السفر المفضل (إلزامي للطيران والبحر، اختياري لتأشيرة فقط)، ومعتمرون اثنان.
- [ ] رفع جواز كل معتمر، وإقامة الضامن (صورة أو PDF). يُرفض ملف من نوع غير مسموح برسالة واضحة.
- [ ] الإجمالي = السعر × عدد المعتمرين، ولا يُرسل الطلب قبل تأكيد الإجمالي.
- [ ] الضغط المزدوج على «إرسال» يُنشئ طلبًا واحدًا فقط.
- [ ] تظهر بعد الإرسال شاشة الدفع: المبلغ، والحساب البنكي مع زر النسخ، وزر رفع الإيصال.
- [ ] تحديث الصفحة أثناء الدفع يعود إلى الطلب نفسه ولا يُنشئ طلبًا جديدًا.
- [ ] بعد رفع الإيصال تظهر الحالة «بانتظار مراجعة الدفع».

### الموافقة الأمنية لمصر
- [ ] الخياران «جوي — مطار القاهرة» و«بري — المعبر» بسعريهما.
- [ ] زر «إرسال طلب الموافقة» معطّل، وتحته سطر يذكر الخانة الناقصة.
- [ ] رفع صورة الجواز (صفحة البيانات). تظهر ملاحظات الجودة للمساعدة فقط ولا تمنع الإرسال.
- [ ] للجوي: جهة القدوم ومطار الوصول. للبري: منفذ الدخول.
- [ ] اختيار «أطلب حجز تذكرة عبر نسائم» اختياري، ولا يؤثر على الموافقة.
- [ ] تظهر شاشة الدفع بعد الإرسال، ثم يُرفع الإيصال.
- [ ] زر واتساب العائم لا يغطي أزرار النموذج على الهاتف.

### التتبع
- [ ] `/track`: إدخال الهاتف ← رمز واتساب ← قائمة الطلبات.
- [ ] تظهر المرحلة الحالية والإجراء المطلوب من العميل.
- [ ] رمز خاطئ يُرفض. الطلب المتكرر للرمز محدود العدد.
- [ ] لا يمكن رؤية طلبات رقم هاتف آخر.

## 2. العميل — تطبيق أندرويد (جهاز حقيقي)

- [ ] تثبيت ملف APK، ثم التأكد من ظهور شارة «بيئة اختبار».
- [ ] الرئيسية: العمرة (الأنواع الثلاثة بأسعارها) والموافقة الأمنية لمصر (جوي/بري) فقط.
- [ ] شاشة «ابدأ طلب» تعرض الخدمتين فقط.
- [ ] رحلة عمرة كاملة كما في البند 1، مع تصوير الجواز بالكاميرا والاختيار من المعرض.
- [ ] رحلة مصر كاملة، مع التصوير بالكاميرا.
- [ ] بعد رفع الإيصال: تبقى شاشة الدفع وتعرض «بانتظار مراجعة الدفع».
- [ ] عند العودة للرئيسية **لا تظهر** بطاقة «طلب بانتظار الدفع» (خلل أُصلح في #151).
- [ ] «متابعة»: التحقق بالهاتف، ثم الطلبات ومراحلها.
- [ ] بعد قبول الدفع من الإدارة: تتحدث الحالة إلى «تم تأكيد الدفع».
- [ ] بعد نشر الملف النهائي: يظهر زر التحميل، ويُفتح الملف.
- [ ] قطع الإنترنت أثناء الرفع: تظهر رسالة واضحة وزر «إعادة المحاولة»، ويبقى الملف المختار.
- [ ] إغلاق التطبيق وإعادة فتحه: الجلسة والطلب محفوظان.
- [ ] الاتجاه من اليمين لليسار، وعدم وجود تمرير أفقي، ووضوح النصوص على شاشة صغيرة.

## 3. الإدارة — موظف عمليات

- [ ] الدخول، ثم القائمة الجانبية: مركز العمليات، الموافقة الأمنية لمصر، طلبات العمرة، مساحة عمل الحالات.
- [ ] **مركز العمليات:**
  - طوابير مصر والعمرة من بيانات حقيقية.
  - الأحمر فقط للمتأخر فعلًا عن موعده.
  - «بلا نشاط 24 ساعة» يظهر بالكهرماني.
- [ ] **`/admin/egypt`:** الترتيب بأقرب تاريخ سفر، والتصفية (المرحلة، الموظف، طريقة الدخول، تاريخ السفر)، والبحث بالاسم أو الهاتف أو المرجع.
- [ ] **تبويب «الموافقة الأمنية»:**
  - رفع الموافقة قبل قبول الدفع **يُرفض** برسالة الخادم.
  - بعد قبول الدفع وقبول المستندات: رفع الموافقة ← بدء تجهيز التعميم ← تاريخ السفر مع السبب ← التذكرة ← بيانات الرحلة ← رفع التعميم (PDF فقط).
- [ ] **`/admin/umrah`:** تصفية بالدفع ونوع الباقة والموظف، والترتيب بالإجراء المطلوب.
- [ ] **تبويب «العمرة»:** المراحل، والإجراء التالي، والضامن مع حالة الإقامة، ومستندات كل معتمر.
- [ ] **قبول المستندات ورفضها:** الرفض يتطلب سببًا، ويظهر للعميل.
- [ ] **التنفيذ:** بدء التنفيذ ← رفع ملف نهائي لكل معتمر ← يُغلق الطلب تلقائيًا «مكتمل».
- [ ] **الملاحظات الداخلية:** لا تظهر للعميل.
- [ ] **«السجل»:** كل إجراء مسجل باسم الموظف ووقته.

## 4. الإدارة — محاسب

- [ ] القائمة: الدفعات والتقارير و«طلبات العمرة» للاطلاع فقط، ولا يظهر «مجموعات العمرة».
- [ ] **مراجعة الدفعات:** فتح الإيصال ← قبول الدفع ← يصدر «إيصال سداد». ضغطتان متتاليتان على القبول تُسجلان قبولًا واحدًا.
- [ ] رفض إيصال مع ذكر السبب: يرى العميل السبب، ويستطيع رفع إيصال جديد.
- [ ] لا يستطيع: بدء التنفيذ، أو قبول المستندات، أو فتح طابور مصر (يُرفض).

## 5. الإدارة — مدير / مدير أعلى

- [ ] إسناد طلب لموظف، ويظهر في «طلباتي» لديه.
- [ ] الأسعار: تعديل سعر باقة، ثم التأكد من أن طلبًا أُرسل بالسعر القديم يُرفض ويُطلب تأكيد السعر الجديد.
- [ ] المستخدمون: إنشاء موظف وتعطيله، ثم التأكد من انتهاء جلسته.
- [ ] «المظهر» يغير ألوان الموقع العام فقط، لا لوحة الإدارة.
- [ ] «سجل النشاط» يعرض العمليات الحساسة.

## 6. الأمان والبيانات (عينة يدوية)

- [ ] رابط ملف مستند بدون تسجيل دخول: يُرفض.
- [ ] نسخ رابط دفع ثم تغيير الرمز فيه: يظهر «غير موجود».
- [ ] أرقام الجوازات مخفية جزئيًا في قوائم الموظفين.
- [ ] تسجيل الخروج ثم زر «رجوع» في المتصفح: لا تظهر بيانات اللوحة.

## 7. بعد الاختبار

- [ ] أغلق طلبات الاختبار بنتيجة «ملغي» من اللوحة. **لا تحذف أي بيانات.**
- [ ] سجّل النتائج في `TASKS.md` مع أرقام الطلبات.
