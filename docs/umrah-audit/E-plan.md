## بوابات التسليم

1. PR إصلاحات P0 منفصل مع regression tests؛ لا إخفاء الاختبار الفاشل U-02 أو تخفيف assertion.
2. P1 على أجزاء صغيرة متوافقة؛ migration additive في قاعدة معزولة أولًا، واختبارات عقود بين الويب والهاتف والإدارة.
3. اختبار رحلة واحدة وعدة معتمرين لكل نوع، رفض مستند/إيصال، دفع متكرر، نشر جزئي، تذاكر اختيارية، IDOR وتزامن، والجلسات مع شبكة متقطعة.
4. Playwright حقيقي على بيئة اختبار، build Android وجهاز فعلي، ثم استعادة backup مثبتة قبل طلب إطلاق. تبقى أسعار التطوير دون تغيير حتى قرار مالي منفصل.
5. موافقة المالك قبل أي دمج أو نشر أو migration إنتاجية؛ الموافقة على تقرير التدقيق ليست موافقة نشر.
