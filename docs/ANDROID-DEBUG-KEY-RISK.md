# مفتاح التوقيع التجريبي (debug) المحفوظ في المستودع — الخطر وخطة الإزالة

## أين هو بالضبط

| الموضع | ما فيه |
|---|---|
| `mobile/android-debug.keystore.b64` | المفتاح نفسه بترميز base64 (مخزن بالاسم المستعار `androiddebugkey`، كلمة المرور `android`) |
| `.github/workflows/android-apk.yml` (خطوة «Restore stable QA signing key») | يفك الملف إلى `mobile/android/debug.keystore` ويتحقق من بصمة الشهادة `cd7447b277c7d1dbefcac2aa4751993bca3027afdec8d9bfb7a644ad9464fc72` |
| `mobile/android/app/build.gradle` (`signingConfigs.release`، الفرع الاحتياطي) | يستخدمه فقط إذا لم يوجد `NASAEM_RELEASE_KEYSTORE`؛ ويرفضه `-PrequireReleaseKey=true` |
| `.github/workflows/android-release.yml` | يرفض صراحةً أي APK موقّع بهذه البصمة |
| `mobile/README.md`, `docs/ANDROID-RELEASE.md` | إشارات توثيقية |
| `mobile/android/.gitignore` | يتجاهل `debug.keystore` الناتج عن فكّ الملف |

## الخطر

المفتاح وكلمته معلنان لكل من يرى المستودع (وهو عام). من يملك المفتاح يستطيع توقيع APK بنفس الهوية؛ فأي جهاز مثبت عليه نسخة موقّعة بهذا المفتاح يقبل «تحديثًا» خبيثًا موقّعًا به. لذلك **لا تُوزَّع أي نسخة موقّعة به على العملاء**. النسخة النهائية تُوقَّع بمفتاح الوكالة الجديد (أسرار GitHub فقط)، وهي لا تقبل التحديث فوق النسخ القديمة (حذف مرة واحدة).

الحماية القائمة الآن: workflow الإصدار يفشل إن لم تتوفر أسرار التوقيع، ويفشل إن كانت البصمة هي بصمة المفتاح التجريبي، ويفشل إن لم تطابق `ANDROID_RELEASE_CERT_SHA256`؛ وملفات `*.keystore/*.jks/*.p12` مُتجاهلة في Git؛ واختبار في `mobile/tests` يتحقق ألا يُتتبَّع أي ملف مفاتيح غير الملف التجريبي.

## خطة الإزالة الآمنة (في PR مستقل لاحقًا — لا تُنفَّذ الآن)

1. **بعد** صدور أول إصدار موقّع بمفتاح الوكالة وتسجيل بصمته في `ANDROID_RELEASE_CERT_SHA256`.
2. تغيير بناء الـPR في `android-apk.yml` ليولّد مفتاحًا مؤقتًا لكل تشغيل (`keytool -genkeypair` داخل الـjob، يُحذف بانتهائه) بدل فكّ الملف المحفوظ، ويحذف خطوة التحقق من البصمة الثابتة.
3. حذف `mobile/android-debug.keystore.b64`، وفرع التوقيع الاحتياطي في `build.gradle` (يصبح البناء بلا مفتاح الإصدار فاشلًا أو يستخدم مفتاح debug القياسي لأندرويد للبناء المحلي فقط)، وسطر `debug.keystore` في `.gitignore` إن لم يعد لازمًا، وإشارات README.
4. اختبار: بناء PR يمرّ بمفتاح مؤقت، وAPK الإصدار يمرّ بمفتاح الوكالة، وfails عند غياب الأسرار.
5. **لا إعادة كتابة لتاريخ Git**: المفتاح التجريبي عام أصلًا ولا قيمة سرية فيه؛ تدويره يتم باعتماد مفتاح الوكالة وحده. إعادة الكتابة تكسر كل الفروع والـPRs المفتوحة وتفيد أقل مما تضر.
6. بعد الدمج: التأكد من أن النسخ التجريبية القديمة ما زالت تُحذف يدويًا من أجهزة الاختبار.
